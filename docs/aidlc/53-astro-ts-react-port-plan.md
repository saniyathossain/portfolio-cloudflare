# 53 — Astro + TypeScript + React islands port (exact parity) + GA section tracking (plan)

## Context

Owner wants the site (static `public/index.html` + Alpine + hand-written JS, Cloudflare Worker) converted to
**Astro + TypeScript + React islands**, with the page looking and behaving **exactly the same** (UI, effects,
motion, interactions), but refactored/optimized. Also: **every section tracked in Google Analytics**, with the
JSON shaped to drive that, and a verdict on **SQLite vs JSON** for content. Direction was set in doc 52
(package.json + TS, Astro islands, shadcn later, Cloudflare free tier).

Key facts from exploration:
- Content: `public/assets/data/portfolio.json` (~28 KB) fetched at runtime by `data.js` → `_hydrate()` →
  `window.PORTFOLIO_DATA`; Alpine (`portfolioApp()`, `skillsFlatPanel()`, `editorialHelpers()`) renders loops.
  Most transforms are **pure** (BRANDS/tints, `_groupExperiences`, `highlightExp`, partners, templating) → move
  to build time. Date-dependent ones (`_yearsSince`, "Present" tenure, year) stay tiny client calcs or build-time
  (rebuild cadence acceptable — decide per item).
- `<head>` is generated by `scripts/sync-head.js` (meta/OG/JSON-LD/critical CSS inline/analytics tags) →
  becomes an Astro `BaseHead` component.
- Analytics today: only `buildAnalytics()` in `sync-head.js:63-77`; ids empty → zero requests; **no event
  tracking**. CSP already allow-lists gtag + GA hosts. Section ids: `#home #about #services #experience #skills
  #editorial #education`; "Create band", "Stats", footer have **no id**; scroll-spy (`app.js:249-263`) only
  watches `nav` ids.
- Worker `src/index.js`: CSP (has `'unsafe-eval'` only for Alpine), Early Hints, cache headers, flag merge on
  portfolio.json (`SKILLS_SCROLL_DESIGN`), maintenance 503 + preview bypass, `/api/contact` (Turnstile/KV/email).
- Build: esbuild via npx, Tailwind 3.4.19 standalone binary, macOS-only image tools, asset-version + SW hash
  scripts that rewrite source files.

## Approach

### 0. Parity contract (governs everything)
- **CSS kept verbatim**: `styles.css`, `critical.css`, `tailwind.css` utilities move as-is; every class name,
  `data-*` hook and JS-set custom property (`--px/--py`, `--stagger-i`, `--row-i`, `is-open`, `is-swapping-*`,
  `html.is-loading/is-ready`) is preserved. Astro components emit the **same DOM** as today's Alpine output.
- **Effects modules ported, not rewritten**: `motion.js`, `reveal.js`, `blur-reveal.js`, `liquid-hero.js`,
  `aurora.js`, `loader.js` become typed TS modules with identical logic and the same gating (idle load,
  `(hover:hover) and (pointer:fine)`, `prefers-reduced-motion`).
- **Timing/order quirks reproduced exactly** (from inventory):
  - The loader runs on its own 650 ms timer (`loader.js`), independent of the data. It sets `html.is-ready` and fires `portfolio-ready`, which starts the effects. Keep the event as a shared bus that islands listen to.
  - The hero card carousel order matters: `cardStep` swaps classes, waits for `transitionend` (240 ms fallback), then `_finishSwap` runs, with the badge pulse driven by `setupHeroBadgeCarousel`.
  - Accordion easing: open 420 ms `cubic-bezier(.34,1.56,.64,1)`, close 300 ms `(.32,.72,0,1)`, lazy mount on first open.
  - Editorial: exit 170 ms → swap → enter → clear 480 ms. The tab lens and search dock heights are released after 460 ms.
  - Touch popover/orb behaviour (now in `app.js:854-928`) must keep working under reduced motion.
  - The scroll-lock sequence: capture `scrollY`, then `body.top`, then on unlock force a reflow and use instant scroll.
- **Known bugs fixed while porting** (behaviour-neutral):
  - A bfcache `pageshow` re-fires `portfolio-ready` and adds duplicate listeners. Make each module's init idempotent.
  - The `[data-count]` stats are scanned only once, which is a race with Alpine. Static markup fixes this.
  - The editorial `init()` runs twice.
  - `createBand` and `sections.editorial` exist in the JSON but are unused. Render create-band from the JSON; decide on the editorial subtitle with the owner.
- **Baseline captured before any change**: screenshots at 360/768/1024/1440 of every section + open states
  (menu, modal, accordion, editorial tabs/search, popovers), and Lighthouse mobile/desktop. Parity checked against
  this baseline at each phase.

**shadcn: not part of this port (owner decision).** This port is a 1:1 parity job: React islands, the same CSS and the same markup. shadcn comes in a later doc, as a separate step, restyled to the Liquid Glass tokens. The islands are structured so their primitives can be swapped for shadcn later.

### 2. Content model — JSON stays, typed + validated (answer to SQLite vs JSON)
- **Verdict: JSON (build-time) now; Cloudflare D1 only if runtime-editable content appears.**
  - Content changes a few times a month, ~28 KB, single editor, read-only for visitors → build-time JSON gives
    zero runtime queries, zero Worker CPU, fully static HTML (best PageSpeed), git history = content history.
  - SQLite would mean D1 (Cloudflare's SQLite) + Worker queries per request or a build step that reads D1 — more
    moving parts, slower TTFB, no benefit at this scale.
  - Already-dynamic data stays where it is: contact submissions → KV; maintenance mode → Worker var (feature
    flags become build-time JSON per owner decision).
  - Revisit D1 if: an admin UI edits content live, comments/likes/view counts, or articles need runtime search
    over hundreds of items.
- Move file to `src/content/portfolio.json` (or split into Astro **content collections** per key) with a **Zod
  schema** (`src/content/config.ts`) → build fails on bad data. Types generated for components.
- Port pure transforms from `data.js` into `src/lib/portfolio.ts` (brandOf/BRANDS/tints, groupExperiences,
  highlightTerms, partners, fillTemplate, tenure). Run at build time.
- **Date-dependent values (owner decision: a small client script).**
  - The build renders tenure labels and the footer year statically.
  - A ~1 KB TS module recomputes "Present"-role tenure, company tenure and the year on load, using `data-tenure-start`/`data-tenure-end` attributes. The labels stay accurate without a rebuild, as they are today.
- **New `sections` registry in JSON** (drives rendering order + analytics):
  ```json
  "sections": [
    { "id": "home", "label": "Home", "component": "Hero", "track": true, "nav": true, "icon": "home" },
    { "id": "about", "label": "About", "component": "About", "track": true },
    { "id": "create-band", "label": "Code, ship, scale", "component": "CreateBand", "track": true },
    { "id": "services", "label": "Services", "component": "Services", "track": true, "subtitle": "…" },
    { "id": "experience", ... }, { "id": "skills", ... }, { "id": "editorial", ... },
    { "id": "stats", ... }, { "id": "education", ... }, { "id": "footer", ... }
  ]
  ```
  Replaces today's `sections` subtitle map + `nav` duplication (nav derived from `nav: true`); every section gets
  an id (adds `create-band`, `stats`, `footer`). `index.astro` loops the registry → component map.

### 3. Rendering split
- **Static Astro components (no JS)**: Hero (image, h1, eyebrow, rating, watermark), About, CreateBand,
  Services, Experience shell + rows, Skills (both layouts, flag chosen at build), Editorial list markup, Stats
  markup, Education, Footer, BaseHead (meta/OG/Twitter/JSON-LD/critical CSS inline/preloads).
- **React islands** (state + behaviour only, same markup/classes):
  `Header` (nav pill, scroll state, clock), `HeroCards` (carousel `cardStep/_finishSwap`), `NavOverlay` (menu,
  scroll lock), `ContactModal` (form, Turnstile lazy-load, success/error, `uc('contactForm')`), `ExperienceAccordion`
  (`toggleRole` + `_animateHeight`, lazy-mount on first open), `Popovers` (tenure/orb dismissal, Esc/visibility),
  `SkillsFlat` (mobile "view more"), `Editorial` (tabs, search, filter swap, dock/lens, count tickers),
  `BackToTop`, `StatsCounter`. Hydration: `client:idle` for header/hero, `client:visible` below the fold.
  Shared UI state (menu/modal open, scroll lock) via a tiny store (nanostores) instead of Alpine root state.
- Non-component effects (`motion`, `reveal`, `blur-reveal`, `aurora`, `liquid-hero`, `loader`) load as plain TS
  modules via Astro `<script>` with the existing idle/desktop gates — no React overhead.
- Alpine removed at the end → drop `'unsafe-eval'` from CSP.

### 4. Google Analytics section tracking
- Config stays opt-in: `site.analytics.googleId` empty ⇒ no tags, no requests (non-negotiable preserved).
- `src/lib/analytics.ts`: loads gtag only when id set (after idle), `track(event, params)` no-op otherwise;
  respects reduced data/DNT optional.
- **Non-blocking + fully configurable (owner requirement, 2026-11-24).** Any third-party dependency (GA,
  Cloudflare Insights, Turnstile…) must:
  - be configured entirely in JSON (`site.analytics`: `googleId`, `scriptUrl`, `loadTimeoutMs`, `loadOn`
    (`idle`|`interaction`), `cloudflareToken`, `beaconUrl`, sample rate/flags) — no hard-coded URL or timeout in code;
  - never block render: injected dynamically after `load`/idle, `async`, never in `<head>` blocking path, never
    awaited by any UI code;
  - fail silent: load timeout (`loadTimeoutMs`), `onerror`, adblock or CSP block → swallow, `track()` stays a no-op,
    no console errors, no retry storm, nothing in the UI depends on it;
  - when not configured (empty id): **no script, no request, no listeners** (not just a disabled call).
- **Section views**: one IntersectionObserver over `[data-track-section]` (from registry `track: true`), fires
  `section_view {section_id, section_label, section_index}` once per page view when ≥50% visible ≥1s; plus
  `section_engaged_time` on leave (optional).
- **Interactions**: `nav_click`, `cta_click` (hero buttons), `contact_open`, `contact_submit {result}`,
  `role_expand {company, role}`, `editorial_filter {platform}`, `editorial_search`, `article_click
  {platform, title}`, `social_click {network}`, `outbound_click`. Elements get `data-track="…"` attributes
  rendered from JSON; one delegated click listener.
- GA4 setup notes in doc: register custom dimensions `section_id`, `section_label`; CSP add
  `https://*.google-analytics.com https://*.analytics.google.com`.

### 5. Cloudflare deploy
- `wrangler.toml`: `assets.directory = "./dist"`, `run_worker_first = ["/", "/api/*"]` (assets free/unlimited);
  Worker keeps CSP/security headers on HTML, Early Hints (hero/CSS/font URLs read from Astro build manifest
  instead of `set-asset-version` rewriting source), maintenance, `/api/contact`. Asset cache headers move to
  `public/_headers` (immutable for hashed `/_astro/*`).
- **Feature flags are build-time (owner decision).**
  - `site.features.flags` and `underConstruction` are read during the Astro build; toggling one means editing the JSON and redeploying.
  - The Worker's `mergePortfolioJson` and the `SKILLS_SCROLL_DESIGN` var are removed.
  - `MAINTENANCE_MODE` stays a runtime Worker var.
- Maintenance preview bug noted (assets also 503 without `?preview`) — fix by exempting `/_astro/*` + `/assets/*`.
- Service worker: keep `sw.js` behaviour (network-first HTML/CSS/JS, cache-first assets), precache from build
  manifest; version hash via a small post-build script.
